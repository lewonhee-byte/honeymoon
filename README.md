# 신혼여행 아카이브 — GitHub만 사용하는 수동 저장

공개 사이트: https://lewonhee-byte.github.io/honeymoon/
저장소: https://github.com/lewonhee-byte/honeymoon

Cloudflare, 별도 서버, 새 서비스 계정, Personal Access Token이 필요하지 않습니다. GitHub Pages에서 화면을 제공하고, 파일 업로드와 GitHub Actions로 기록을 저장합니다.

## 사이트에서 수정하고 저장하기

1. 사이트 하단 **이 기기에서 편집**을 누릅니다. 이 모드는 기기 내 임시 편집이며 GitHub 쓰기 권한을 부여하지 않습니다.
2. 기존 문구·사진·도시·숙소·기록·일정·비용·감상문·자유 편집 기능을 사용합니다.
3. **변경사항 저장**을 누르면 JSON과 새 사진을 함께 담은 **archive-update.zip**이 다운로드됩니다. 이 단계에서는 GitHub에 아직 저장되지 않았습니다.
4. **② GitHub 업로드**를 눌러 GitHub에 로그인합니다. GitHub 저장소 쓰기 권한이 있는 계정이어야 합니다.
5. **choose your files**에서 다운로드한 ZIP 한 개를 선택합니다. 압축을 풀거나 파일 이름을 변경하지 마세요. 저장소 **루트**에 업로드합니다.
6. **Commit changes**를 누릅니다. GitHub가 쓰기 권한을 확인합니다.
7. Actions의 **Deploy archive**가 ZIP을 검증하고 사진·JSON을 하나의 Commit에 반영한 뒤 Pages에 배포합니다.
8. 사이트로 돌아와 **배포 상태**를 누릅니다. 현재 편집본의 JSON과 공개 데이터가 일치하면 **GitHub 저장 및 공개 사이트 배포 완료**가 표시됩니다. 일치하지 않으면 GitHub Actions에서 진행 상태·실패 원인을 확인합니다.

갤럭시 Chrome에서도 다운로드 폴더의 ZIP을 GitHub 업로드 화면에서 선택하면 됩니다. 로컬 편집을 누구나 시작할 수 있지만, GitHub에 영구 반영하는 권한은 저장소 쓰기 권한으로 보호됩니다. 브라우저에 토큰이나 비밀번호를 넣지 않습니다.

## 충돌·실패 처리

업로드 패키지는 편집을 시작할 때의 공개 JSON SHA-256을 담습니다. 다른 기기에서 먼저 저장했으면 Actions가 **CONFLICT** 오류로 중단합니다. 기존 공개 데이터와 사진은 그대로 유지됩니다. 충돌할 때는 로컬 JSON 백업 → 최신 사이트 열기 → 필요한 수정을 병합 → 새 ZIP 생성 순서로 진행하세요. 강제 덮어쓰기는 제공하지 않습니다.

ZIP이 손상되었거나 잘못된 경로·누락된 사진·잘못된 형식이 있으면 데이터 반영과 배포를 중단합니다. 검증이 모두 끝난 뒤 이미지와 JSON을 작업하고 Git Commit을 생성합니다. 사진 업로드 일부만 운영 사이트에 공개되지 않습니다. 실패한 ZIP은 GitHub 루트에 남아 원인을 확인할 수 있습니다. 문제를 해결한 새 ZIP을 같은 이름으로 업로드해 재시도하세요.

Actions가 공개 사이트에 배포를 마치기 전까지 기기 내 임시 기록을 유지합니다. 임시 저장은 브라우저 용량 제한이 있으므로 중요한 수정은 JSON 백업도 내려받으세요. 새로고침 후 편집을 시작하면 임시 기록 복구 여부를 묻습니다. 사진 삭제는 참조만 제거해 다른 콘텐츠와 이전 Commit의 사진을 보존합니다.

## 백업·복원

기존 JSON 백업과 사진을 포함한 단일 HTML 내보내기를 유지했습니다. JSON 불러오기는 현재 내용을 먼저 백업하고 덮어쓰기 확인을 받습니다. 불러온 내용은 ZIP을 GitHub에 올려야 다른 기기에도 반영됩니다.

원본 파일 주소에서만 localStorage에 저장된 기록은 새 사이트에서 직접 읽을 수 없습니다. 원본 페이지에서 JSON 백업을 내려받아 새 사이트에 불러오세요. 같은 출처의 v6–v9 기록은 **이전 기록 가져오기**에서 확인할 수 있습니다. 기존 localStorage를 자동으로 지우지 않습니다.

이전 버전은 GitHub의 `data/travel.json` Commit 이력에서 확인합니다. 이전 JSON을 내려받아 최신 사이트에서 가져온 뒤 새 ZIP으로 저장하거나, GitHub에서 변경을 되돌리는 새 Commit을 만들 수 있습니다. 저장소 이력 강제 수정은 하지 않습니다.

## 사진 제한

기존 사진 13개는 화질 변경 없이 개별 파일로 추출했습니다. 신규 업로드는 JPEG/PNG/WebP/GIF, 원본 한 장 12MiB 이하입니다. 기존 canvas 처리기는 새 사진을 보통 최대 가로 2400px, JPEG 품질 0.9로 변환하며, 특정 편집 화면의 원래 크롭·크기 설정은 보존합니다. PNG 투명도·GIF 애니메이션은 JPEG 변환으로 유지되지 않습니다. 원본 사진은 따로 보관하세요.

한 패키지의 신규 사진은 최대 40개·총 18MB, 변환된 한 장은 8MB, JSON은 24MB입니다. 많이 추가할 때는 나눠 저장하세요. 사진은 SHA-256 파일명으로 관리합니다. 삭제된 사진 파일은 공유 참조와 과거 복원을 위해 자동 삭제하지 않습니다.

## 개발·배포 구조

`index.html`, `config.js`, `css/`, `js/`, `data/`, `images/`가 정적 사이트입니다. `js/package.js`는 의존성 없는 ZIP 생성·검증 도구이고, `scripts/import-update.mjs`는 Actions의 제한된 데이터 가져오기 도구입니다.

```powershell
node tests/verify.mjs
node tests/client.mjs
node scripts/build.mjs
```

Node.js 24 이상이면 별도 라이브러리 설치 없이 검사·빌드할 수 있습니다. GitHub Actions는 root의 `archive-update.zip`을 자동 처리합니다. 외부 방문자는 읽기 전용으로 시작합니다. GitHub Pages 프로젝트 하위 경로를 지원하도록 상대 경로를 사용합니다.

계정에 새 인증 권한을 부여하는 중계 서버가 없으므로 사이트에서 버튼 한 번으로 GitHub Commit을 바로 만드는 자동 저장은 제공하지 않습니다. 대신 ZIP 다운로드 → GitHub 업로드·Commit이라는 수동 단계를 사용합니다.
